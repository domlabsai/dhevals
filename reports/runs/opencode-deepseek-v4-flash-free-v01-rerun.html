Sugestão: trocar o `Promise.race` por um `AbortController` — o `race` só rejeita, mas o fetch continua vivo.

**Correção mínima:**

```ts
export async function processJob(id: string, deps: Deps) {
  const controller = new AbortController();
  const timer = setTimeout(() => controller.abort(), 5_000);
  try {
    const result = await deps.client.fetch(id, { signal: controller.signal });
    await deps.queue.ack(id);
    return result;
  } finally {
    clearTimeout(timer);
  }
}
```

**Trade-off:** o timeout deixa de ser uma rejeição sintética do `race` e vira `AbortError` do fetch — quem fizer `match` na mensagem/erro antigo do timeout precisa se adaptar (ou rewrap o erro). Segundo, o `ack` agora só roda em sucesso: jobs que estouram o timeout **não** são ackados e serão redeliverados, em vez de ack de um trabalho inacabado. Em troca, a conexão HTTP é de fato abortada (libera socket, evita a segunda requisição duplicada em produção) e o timer é sempre limpo (sem leak).

**Teste de regressão (Vitest, fake timers — prova abort após 5 s sem esperar de verdade):**

```ts
import { describe, expect, it, vi, beforeEach, afterEach } from 'vitest';

describe('processJob', () => {
  beforeEach(() => vi.useFakeTimers());
  afterEach(() => vi.useRealTimers());

  it('aborta o sinal após 5 segundos e não faz ack', async () => {
    let signal: AbortSignal | undefined;
    const deps = {
      client: {
        fetch: vi.fn((_id: string, opts?: { signal?: AbortSignal }) => {
          signal = opts?.signal;
          return new Promise((_, reject) => {
            signal!.addEventListener('abort', () =>
              reject(new DOMException('aborted', 'AbortError')),
            );
          });
        }),
      },
      queue: { ack: vi.fn() },
    };

    const pending = processJob('j1', deps as any);
    expect(signal?.aborted).toBe(false);

    await vi.advanceTimersByTimeAsync(5_000);

    expect(signal?.aborted).toBe(true);
    await expect(pending).rejects.toThrow('aborted');
    expect(deps.queue.ack).not.toHaveBeenCalled();
  });
});
```

O teste segura o `signal` passado ao fetch, avança o relógio 5 s e verifica que `signal.aborted` virou `true` — cobrindo exatamente o bug de recursos não liberados.
